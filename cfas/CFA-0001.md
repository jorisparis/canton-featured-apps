## 2. App summary

Open Cap Table Protocol (OCP) provides blockchain-based cap table management using the Open Cap Format (OCF) standard. The system records stock issuances, transfers, convertible notes, equity compensation, and other securities transactions on Canton Network with cryptographic proof and immutable audit trails. OCP enables companies to maintain authoritative ownership records with privacy-preserving workflows and real-time position tracking.

---

## 3. Role of Canton Network

- **Cap table registry and ledger infrastructure** — Immutable record of securities ownership and transactions
- **Audit trail** — Cryptographic proof and tamper-evident history for all cap table changes
- **Privacy-preserving transaction finality** — Confidential settlement of securities transactions between parties

### 5.2 Emission strategy

- **Emission basis:** Value-proportional
- **Rate limiting:** Throttled (1–5 TPS via on-chain CouponMinter contract)
- **Calculation:** `ceiling(transactionValue / 100)` — 1 app marker per $100 of transaction value, rounded up per individual transaction

#### Value calculation by transaction type

| Transaction Type | Value Source |
|------------------|--------------|
| StockIssuance | quantity × share_price |
| ConvertibleIssuance | investment_amount |
| EquityCompensationIssuance | quantity × exercise_price |
| WarrantIssuance | quantity × purchase_price |
| StockTransfer | quantity × fair market value |
| ConvertibleTransfer | investment_amount (from original issuance) |
| EquityCompensationTransfer | quantity × exercise_price |
| WarrantTransfer | quantity × purchase_price |

#### Examples

| Transaction | Value | App Markers |
|-------------|-------|-------------|
| 1,000 shares at $5/share | $5,000 | 50 |
| $1,000,000 SAFE investment | $1,000,000 | 10,000 |
| 10,000 options at $2 strike | $20,000 | 200 |
| 3 separate $150 transfers | $150 each | 6 (2 each, not 5 for $450 total) |

#### Minting approach

App markers are minted **asynchronously** after transaction finality using a dedicated CouponMinter contract. The contract enforces TPS limits on-chain to prevent network flooding and maintain healthy app marker economics. Rounding is applied **per individual transaction**, not aggregated across batches.

### 5.3 Non-emitting activities

The following OCF object types do **not** generate activity markers:

- **Setup objects:** Issuer, Stakeholder, StockClass, StockPlan, StockLegendTemplate, VestingTerms, Valuation, Document
- **Acceptances:** StockAcceptance, ConvertibleAcceptance, EquityCompensationAcceptance, WarrantAcceptance
- **Cancellations:** StockCancellation, ConvertibleCancellation, EquityCompensationCancellation, WarrantCancellation
- **Retractions:** StockRetraction, ConvertibleRetraction, EquityCompensationRetraction, WarrantRetraction
- **Conversions/Exercises:** StockConversion, ConvertibleConversion, EquityCompensationExercise, WarrantExercise
- **Corporate actions:** Adjustments, splits, consolidations, pool changes
- **Other transactions:** Repurchase, Reissuance, Release, Repricing, Vesting events, Status changes

## 6. Abuse mitigation (descriptive)

- **Economic friction:** All transactions involve real securities with legal and regulatory implications. Creating fake cap table entries carries significant legal risk.
- **Access controls:** Cap table management requires authorized issuer access. Only verified company administrators can execute transactions.
- **Rate limiting:** CouponMinter contract enforces TPS limits on-chain, providing a hard guarantee that cannot be bypassed even if backend systems are compromised.
- **Real economic activity:** Each app marker corresponds to a finalized securities transaction with ledger proof. There is no mechanism to generate app markers without recording actual cap table changes.
